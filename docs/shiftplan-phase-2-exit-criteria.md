# ShiftPlan Phase 2 Exit Criteria

Phase 2 is private beta polish, app experience, tester feedback, and product usability.

## Phase 2 Ends When

- 10-20 beta users have tested `/app`.
- 50% or more invited users log in.
- 50% or more logged-in users generate a plan.
- 30% or more testers leave feedback.
- Several users say they would use ShiftPlan weekly.
- Several users say they would pay or have already paid.
- Repeated UX complaints are addressed or clearly parked.
- Fresh generated plans are timeline-based and understandable.
- Calendar export and checklist features are not causing repeated confusion.
- No major safety, quality, privacy, or trust issues are open.

## Evidence To Collect

- Login count compared with invites sent.
- Generated plan count compared with users logged in.
- Feedback submission count.
- Would use weekly responses.
- Would pay responses.
- Common friction themes.
- Screenshots or recordings of confusing mobile moments.
- Manual QA results for fresh generation, checklist, calendar export, copy buttons, feedback, and App Access Codes.

## Phase 3 Starts With

- Public beta planning.
- Real account system planning.
- Paid/free app access planning.
- Stronger onboarding.
- Possible iOS prototype planning.

## Still Not Phase 3 Until Proven

- Supabase Auth.
- Public account creation.
- Stripe subscription gating.
- Customer portal.
- Native iOS app.
- Push notifications.
- Google or Apple Calendar sync.

## Decision Rule

Move to Phase 3 only when private beta behavior shows repeat weekly use, clear willingness to pay, and no unresolved high-risk UX or safety issues.
