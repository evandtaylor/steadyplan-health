# ShiftPlan Private Beta Ops Checklist

Use this checklist when inviting and managing private beta testers for the `/app` experience.

## Tester Setup

1. Create an app access code in `/admin`.
2. Set the tester email, label, monthly limit, daily limit, notes, and active status.
3. Copy the beta invite message immediately after creating the code.
4. Send the invite manually.
5. Confirm the tester can log in at `https://www.shiftplan.ai/app`.
6. Ask the tester to save preferences before creating the first request.
7. Ask the tester to create one real weekly request with exact shift days and times.
8. Confirm a generated plan appears.
9. Review the tester in the App Beta admin view.
10. Read their feedback after they review or use the plan.
11. Follow up after 3-7 days.
12. Ask whether they would use ShiftPlan weekly and whether they would pay $9/month.

## What to Check in Admin

- Tester email and status
- Access code label and limits
- Last seen date
- Plans used this month and today
- Weekly request count
- Saved plan count
- Feedback count
- Latest request
- Latest saved plan
- Latest feedback
- Saved preferences summary
- Recent usage events

## Copy/Paste Follow-Up Message

```text
Hey! Quick ShiftPlan beta check-in:

1. Did the plan feel realistic for your actual week?
2. What worked?
3. What felt unrealistic or annoying?
4. What did ShiftPlan assume wrong?
5. Would you use this weekly if it kept improving?
6. Would $9/month feel fair if it reliably helped plan your week?
7. What is the one feature you would want next?

No need to be polite. The honest version is the useful version.
```

## Beta Tracker Fields

Use these fields in a spreadsheet, notes doc, or CRM-lite tracker:

- name
- email
- access code label
- shift type
- generated plan?
- feedback?
- would use weekly?
- would pay?
- biggest issue
- best idea

## Operating Notes

- Use fake/test accounts only for QA.
- Use real tester emails only with permission.
- Track access-code labels, not raw access codes.
- Do not send automated emails yet.
- Do not promise native iOS, reminders, calendar sync, or public accounts as live features.
- Keep feedback focused on weekly planning usefulness, output quality, mobile usability, and repeat use.
- Keep safety boundaries clear: ShiftPlan is lifestyle and routine planning only.
