# ShiftPlan Private Beta Tester Tracker Template

Use this template to track the first 3-20 private beta testers without adding product complexity too early. The goal is to spot repeated patterns, not collect perfect analytics.

## Operating Guidance

- Start with 3-5 testers.
- Fix obvious onboarding, generation, checklist, and calendar issues before expanding.
- Expand to 10-20 testers only after the first group can complete the core flow without hand-holding.
- Look for repeated patterns before building new features.
- Keep feedback tied to real usage: login, request creation, generated plan, checklist, calendar export, and willingness to use weekly.
- Do not treat one interesting request as a roadmap by itself.

## Tester Status Definitions

- Invited: access code created and message sent, but no confirmed login yet.
- Active: tester has logged in and is moving through the flow.
- Needs follow-up: tester got stuck, has not generated a plan, or has not responded after first use.
- Paused: tester is not available right now or is not a fit for the current beta.
- Complete: tester generated at least one plan and gave enough feedback to inform the next decision.

## What To Look For

- Repeated friction before plan generation.
- Repeated confusion around saved preferences versus this week's request.
- Generated plans that feel too long, too robotic, or not timeline-based enough.
- Checklist or calendar export issues on iPhone.
- Whether testers understand this is lifestyle/routine planning only.
- Whether testers would use ShiftPlan weekly without a reminder from the founder.

## Weekly Review Questions

- How many invited testers logged in?
- How many generated a plan?
- How many used the checklist?
- How many tried calendar export?
- What is the most repeated complaint?
- What is the most repeated positive signal?
- Which feature request showed up more than once?
- Is it time to invite more testers, or should the current issue be fixed first?
